# t-rec

**Toolbox。** 各種實用迷你工具的總站。

一個工具進了 t-rec，就**交出自己的招牌**：不自帶域名、不自帶 favicon、不自帶代號、沒有 roadmap。
它從此是「工具箱裡的一把工具」，不是「一個專案」。

**這是划算的交換。** 一個記事本、一個書籤管理，單獨拿出去撐不起一個專案——網上一大堆。
但十個這樣的工具撐得起一個工具箱。**t-rec 的份量由數量堆出來**，工具交出撐不起來的招牌，
換到的是 t-rec 這塊撐得起來的門面。

**但畫風不交出去。** 每個工具保有自己的視覺與一個代表色 —— 工具箱不是產品線，不需要家族風格。

---

## 成員

| 工具 | 一句話 | 代表色 | 原位置 |
|---|---|---|---|
| [`notes/`](./notes/) | 簡單記事本，寫作 + 自動儲存 + 匯出單檔 `.md` | `#00ff5e` 系統綠 | `CommonLibrary/memo-rec/` |
| [`bookmarks/`](./bookmarks/) | 極簡書籤 / 書櫃，封面卡片 + 進度 + 連結 | `#0000ff` | `exe-rec/b/`（BMK） |

`notes` 的前端對齊 b-rec / lib-rec 家族語言；`bookmarks` 維持自己的卡片風格。
**兩者刻意不統一** —— 見下方「畫風：不統一」。

## 收容判準

### 該進 t-rec — 七條**全部**成立

| # | 判準 | 具體怎麼驗 |
|---|---|---|
| 1 | **單一動作** | 一句話說得完它做什麼；沒有「還有…」 |
| 2 | **空殼交付** | 出廠是空的容器，資料由使用者填。**不預載 Rec 的任何內容** |
| 3 | **微型** | 單檔 `index.html` 或單支腳本等級。無 build、無後端、無 `node_modules`、無多頁路由 |
| 4 | **無品牌（不自帶）** | 不自帶域名 / CNAME / favicon / logo / 代號縮寫進來。**自有配色可留**，但不得是原宿主的識別色 |
| 5 | **架構固定** | 功能與資料模型定了就不動。沒有 roadmap、沒有版本演進計劃，壞了才修 |
| 6 | **體量不足以獨立成案** | 單獨拿出去當一個專案，撐不起來 |
| 7 | **零專案依賴** | 不依賴任何大專案的資料 / 建置 / 部署 |

> **第 2 條是主判準**（其餘多為推論），**第 6 條是存在理由**。
> 判斷法：**把它原封不動給一個陌生人，他能立刻開始用嗎？**
> `notes` 空的可以用；`rechealth` 空的沒有意義（它承載 Rec 的體測數據）——差別就在這。

#### 判準 6 · 體量不足以獨立成案

驗法：**這東西單獨拿出去當一個專案，撐得起來嗎？**

「單純的記事本」「書籤管理」網上一大堆，沒有獨特性、沒有規模、沒有演進空間 —— 撐不起來，所以進工具箱。

> ⚠️ **這量的是份量，不是品質。** 工具可以做得很好，好 ≠ 有份量。
> `notes` 的前端做得比多數同類乾淨，但它仍然只是個記事本。

**關於域名**：判準 4 的「無域名」是指**工具不得自帶域名進來**，不是 t-rec 永遠不能開子域名。

`bookmarks.rec.ooo` 這類子域名若要開，定位是**對外推廣用的短入口**，
行為是 **301 永久轉址**到 `t-rec/bookmarks` —— 它不是工具的家，只是一塊指路牌。

| | |
|---|---|
| 用途 | 貼到站外的推廣連結（短、好記、單獨可分享） |
| 行為 | **301 → `t-rec/bookmarks`**，不是獨立部署、不是鏡像 |
| 廣播 / 自我介紹 | **一律用 t-rec 的網址**，不用子域名 |
| 工具歸屬 | 確定收進 t-rec 家族的就**維持在家族內**，不因為有子域名而獨立 |

子域名只在「別人要連過來」的方向存在；在「我們怎麼稱呼它」的方向不存在。

#### 判準 7 · 零專案依賴

工具不得依賴任何大專案的資料、建置或部署。

`notes` 沒有掛到 `b-rec` 底下當子模組，就是這個理由：一旦依賴，它會被綁在 b-rec 的
發版節奏、部署管線、資料模型上，兩邊互相拖沓，而且再也無法被單獨搬移或退役 ——
那正是 t-rec 要解決的問題本身。（何況兩者根本不同生態系：b-rec 要編輯內容直接開 `.md` 就好，
不需要一個記事本。）

**t-rec 是平的容器：聚合，不寄生。**

### 不該進 t-rec — **任一**成立即出局

| 類別 | 特徵 | 現有例子 |
|---|---|---|
| **已品牌化** | 有域名 / CNAME、自有配色、專屬 icon、對外掛名 | `kiln`（kiln.ooo）· `Ruvia`（ruvia.dev）· `lib-rec`（accent `#fc036b`、📖）· `b-rec`（📚） |
| **規模超標** | 有 build / 依賴樹 / 多頁路由 / 後端 / 擴充套件 | `PD+FC` · `spiral` · `ArcDeploy_GUI` · `replit-remains` |
| **明確個人服務目的** | 內容是 Rec 的資料或身份，換個人就沒意義 | `exe-rec`（**標準反例**）· `rechealth` · `mygraph` · `nest` · `rec-pf` · `s-rec` · `zenn-rec` |
| **內容庫，不是工具** | 主體是文件 / 素材 / 筆記，程式只是外殼 | `CommonLibrary` · `prompt` · `derivatives` · `mom-pack` · `baobao` · `Treasures` |
| **基建** | 管的是機隊 / 部署 / 專案本身 | `sov/machine` · `sshtools` · `map-rec` · `park` |
| **體量足以獨立成案** | 有獨特性 / 有規模 / 架構仍在演進，單獨拿出去撐得起一個專案 | `kiln` · `Ruvia` · `rechealth`（架構隨健康主題持續長，非固定） |

### 四個容易搞混的邊界

- **「小」不等於「該進」。** `park/braintank` 只有一個 `index.html`，但它是佔域名的停泊站——屬**基建**。
- **「通用」不等於「該進」。** `porkbread`（Porkbun CLI）通用又零依賴，但它服務的是 Rec 的域名資產管理——屬**個人服務**。
- **「個人用」不等於「不該進」。** t-rec 裡的工具當然是 Rec 在用。關鍵是**工具本身不認識 Rec**。
- **「體量不足」不等於「做得爛」。** 判準 6 量的是份量不是品質。一個很好的記事本仍然只是個記事本；
  反過來，粗糙的半成品也不會因為粗糙就有資格進來 —— 它還得先過判準 5（架構固定）。

## t-rec 模式（進來要改什麼）

搬進 t-rec 的專案一律做這四件事：

1. **刪 favicon** —— 不掛個體 emoji / icon。（`notes` 的 📝、`bookmarks` 的 🔖 皆已刪）
2. **收斂為單一 accent** —— 一個工具只准一個強調色。
   `notes` 原 `#ff0000` → 現 `--accent: #00ff5e`（系統綠，對齊 b-rec token 命名）；
   `bookmarks` 原 `--bmk-red #e2402f` + `#1a6fd4` → 現 `--t-accent: #0000ff`。
3. **刪反向導鏈** —— 原專案首頁指向它的連結、轉址頁、docs 條目全部移除。舊網址**不做轉址**。
4. **去代號** —— 縮寫代號（BMK 之類）改成語意詞（`bookmarks`）。資料夾名 = 工具名 = `<title>`。

**唯一例外：`localStorage` key 不改。** `memo.notes.v1`、`bmk-cards-v1` 保留 legacy 名——
那是內部識別碼不是品牌，改了會讓既有資料全部消失。各工具 README 已註記。

### 畫風：不統一

t-rec **不是產品線，沒有家族畫風**。各工具保留自己的風格，只要求「不再指向原宿主」。
上面第 2 條要求的是**收斂**（一個工具一個強調色），不是**對齊**（大家用同一個色）。
`notes` 是 `#00ff5e`、`bookmarks` 是 `#0000ff`，各自獨立選定。

- **沒有自有畫風的新工具** → 保底參考 `pp-bin.bin`（極簡終端 hub）或 `Ruvia`（ambient 低對比工作台）。
- **hub（`index.html`）獨立設計，不從子工具推導。** 否則 hub 會被「最近搬進來的那個工具」綁架，
  並暗示一個實際上不存在的家族風格。現行 hub 沿用 pp-bin 首頁的語言：
  居中 `<pre>`、`rgba(0,0,0,0.05)` 淡灰底框、整行 hover 反底、`.site-note` 於 hover 才追加 `-> /dir`、
  `.site-sizer` 固定底框寬度、就地展開不離開本頁。
  **新增工具 = hub 加一行 + 同步 sizer + MANUAL 加一段 + 更新上面成員表。**

## MANUAL（給使用者的說明）

說明文件分**三層，不得互相滲透**：

| 層 | 位置 | 對象 | 寫什麼 |
|---|---|---|---|
| **hub MANUAL** | `index.html` 內嵌，點 `MANUAL` 就地展開 | 一般使用者 | 這站是什麼 · 每個工具**幹什麼** |
| **工具 manual** | 各工具的**種子內容** | 該工具的使用者 | **怎麼用**——就地示範 |
| **README.md** | 本檔與各工具目錄 | 開發者 / AI | 判準 · 設計決策 · legacy 註記 |

- hub MANUAL **全英語**、字數受控（現行 ~90 words）、**只做功能性描述**。不寫操作步驟。
- **首頁不連 README** —— 你正在讀的這份是給開發者看的，不該出現在使用者入口。
- 結尾固定 `BY REC DUNGEONS`（hover 轉藍、連 `rec.ooo`）+ `↩︎` 收合。

### hover 語義（兩類，不可混用）

| 類 | 例 | hover 行為 | 進 `.site-sizer`？ |
|---|---|---|---|
| 導向連結 | `notes` `bookmarks` | 追加 ` -> /dir` | ✅ |
| 就地展開 | `MANUAL` | **只反底，內容不變** | ❌ |

`-> /dir` 承諾了「點下去會離開本頁、到某個路徑」。就地展開的項目套用它就是說謊。

### 工具 manual = 種子內容（待做）

用法示範寫成該工具的**第一筆資料**，不另開說明頁：

| 工具 | 種子內容 | 狀態 |
|---|---|---|
| `notes` | 一則初始筆記，內容即用法說明 | 待做 |
| `bookmarks` | 一張示例卡（封面圖 + 書名 + 頁碼進度 + 連結） | 待做 |

使用者刪得掉（就是一筆普通資料），且順帶解掉空狀態逃生口的問題。
判準 2 禁的是**預載 Rec 的內容**，種子內容是**通用示範**，不衝突。

## 怎麼開

線上入口：**https://t.rec.ooo**。

本機開發：雙擊 `rituals/自動localhost.command` → `http://127.0.0.1:9090/`，
一個 server 同時涵蓋 `/notes/` 與 `/bookmarks/`。單開某個工具走該工具自己的 `rituals/`。

| 入口 | Port | 說明 |
|---|---|---|
| `t-rec/rituals/` | **9090** | hub，涵蓋全部工具 |
| `t-rec/notes/rituals/` | 9091 | 單開 notes |
| `t-rec/bookmarks/rituals/` | 9092 | 單開 bookmarks |

登記於 [`sov/machine/ports.md`](../sov/machine/ports.md) 的 9xxx 段（2026-08-07 新開的 toolbox 家族）。

> ### ⚠️ localStorage 綁 origin —— 「資料不見了」的唯一成因
>
> 兩個工具都把資料存在瀏覽器的 localStorage，而 localStorage 是**按 origin 隔離**的。
> `https://t.rec.ooo`、`127.0.0.1:9090`、`127.0.0.1:9091`、`file://…` 是**不同的 origin，資料互不相通**。
>
> **固定用同一個入口**，否則每換一次開法就像是一台新機器。正式使用建議固定走 `https://t.rec.ooo`；本機開發固定走 hub（9090）。

## 疑難排解

**開 `bookmarks/` 是一片全白？（2026-08-07 已修）** 兩個原因疊在一起，都不是搬壞的：

1. **空狀態本來就全白。** 原本 `.add-icon { opacity: 0 }` —— 加卡的 `＋` 完全隱形，
   要把游標移到左上角第一格才浮到 `opacity: 0.1`。在 `exe.rec.ooo/b/` 上一直有卡片，
   所以真正的空狀態從沒被看見過。
2. **舊書籤沒跟著搬。** 資料存在 `https://exe.rec.ooo` 這個 origin 底下，
   **localStorage 不會跟著檔案移動**，搬到本機必然從零開始 —— 於是第 1 點被觸發。

→ 已加空狀態逃生口 `.add:only-child .add-icon { opacity: 0.22 }`：零卡片時 `＋` 直接可見，
有卡片後自動回到 ambient 行為。舊書籤要救的話，趁 GitHub Pages 還沒重新部署，
去 `https://exe.rec.ooo/b/` 開 DevTools 執行 `copy(localStorage["bmk-cards-v1"])`，
再貼進本機同一個 key。

> **通則**：ambient 設計（元素預設 `opacity: 0`、hover 才浮現）碰上**零內容**狀態，
> 會退化成一張完全不可互動的白紙。t-rec 的工具都是「空殼交付」，**空狀態是常態不是例外**，
> 所以每個 ambient 工具都必須留一個零內容時仍可見的入口。已寫進
> [`19-toolbox`](../sov/machine/specs/19-toolbox.md) 失敗模式。

## 慣例

- **一工具一資料夾**，資料夾名即工具名，小寫、語意詞、不加 `-rec` 後綴（工具箱內不必重複 rec 字根）。
- 每個工具自帶 `README.md`，含：一句話 / 怎麼用 / 儲存位置 / 不做的事。
- `rituals/` 薄殼沿用 `sov/machine/lib/rec-serve.sh` 慣例，`REC_PROJECT="t-rec/<tool>"`。
  成員只裝 `自動localhost.command`；不各自 push / deploy。工具箱根的 `自動push.command`
  統一推送 `recdnd/tool-t.rec`，GitHub Pages 自動發布全站。
- t-rec 整體部署於 **https://t.rec.ooo**；repo 為公開的 `recdnd/tool-t.rec`。
- **域名的主體是 t-rec，不是工具。** 子域名（若開）只作 301 指路牌，廣播一律用 t-rec 網址。
